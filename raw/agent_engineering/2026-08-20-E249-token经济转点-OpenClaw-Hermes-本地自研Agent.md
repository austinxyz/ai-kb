## 大趋势

AI 行业从 **"Token Maxing"**（无脑堆消耗）转向 **"Token Efficient"**（精打细算）。背景：Uber 4 个月烧穿全年 Token 预算，Meta 内部曾搞消耗排行榜刷榜，现在开始限制、劝员工省着用。行业关注点从"科研能力竞赛"转入"工程落地"阶段。

杰文斯悖论在 Token 经济上重演：单价年降 10 倍，但 Agentic Loop 反复调用工具+堆上下文，总消耗反而暴涨百倍不止。

## OpenClaw

**出身**：作者 Peter 是硬核开源工程师，做 OpenClaw 之前 30 天就烧了 **130 万美金** Anthropic API 账单。他觉得个人助理类 Agent 大厂迟早会做，等了几个月没动静，等不及了，用 Claude 花 **一星期 vibe coding** 直接手搓出来。

**定位**：开源、local-first 的个人助理，不是为重度软件工程设计的。核心功能：
- 过滤、分类、自动回复日常邮件（广告自动删，拿不准的决策提示用户确认）
- 精选消化信息（抓 Hacker News、邮件订阅、媒体文章，先出摘要，感兴趣再点开原文）

**文化现象**：社区玩梗叫"养龙虾"（指用户通过本地配置和相处，不断迭代让它更懂自己）。爆火没几天，社区就搞出个叫 **MoltBook** 的产品——让各家的 OpenClaw 互相社交，变成一场技术传播的行为艺术/社会学事件。

**优点**：
- Local-first 保护隐私——极客愿意把全部数据交给 AI，前提是留在本地
- 完全开源，传播力强，扮演了把 Agent 形态普及给大众的"普罗米修斯"角色

**缺点**：
- 一周 vibe coding 产物，代码没精雕细琢，配置复杂、稳定性差
- 记忆功能弱，靠不停 Compaction（对话压缩）或回滚，极耗 Token，还容易记忆混乱、忘事

## Hermes

**出身**：Web3 机构 Nous Research 出品。因为 OpenClaw 记忆和稳定性短板明显，主讲人黄东旭很快迁移到了 Hermes。

**技能沉淀机制（核心巧思）**：不硬解决"完美长期记忆"这个业界难题，而是绕开它——
1. 在 Agent Loop 里加入主动反思机制，不只是执行任务，还监控自己的执行结果
2. 成功完成任务后，做"复盘式总结"，把成功的步骤和经验封装成一个个可复用的**"技能"（Skill）**记录下来
3. 下次遇到类似场景，直接调用沉淀好的最佳实践

**实际表现**：用一段时间后会自动"长出"很多之前操作过的最佳实践，Onboarding 体验和稳定性明显优于 OpenClaw。

**商业模式**：作为聚合大量用户的流量入口，通过帮模型厂商带 Token 消耗、以更低折扣拿到 Token 差价来变现。

## Slock（后改名 Raft）

**出身**：前 Kimi CLI 负责人钱宇超创立。相当于把人类的 Slack 聊天室搬到 Agent 世界。

**工作原理**：
1. 多个 Agent（如 10 个由 Claude Code、Codex 等不同顶级模型驱动的实例）放进同一个聊天频道
2. **上下文隔离**——彼此不共享各自内部运行上下文，只能看到频道里公开发布的信息，避免上下文膨胀导致混乱
3. 用户丢一个复杂任务（如代码审查），指定其中一个 Agent 当负责人
4. **无 Ego 讨论**：Agent 没有自我执念，被反驳了不会炸毛，立刻认同并在新角度上继续深入推演
5. 强制终止条件：一直"开会"挑刺，直到"谁也挑不出更多毛病"才停

**具体案例**：黄东旭常用这个多 Agent 团队审查复杂系统级软件（如分布式数据库 db9）。单点模型面对几千行、涉及七八个模块的复杂改动容易顾此失彼、产生幻觉；但 10 个顶级 Agent 互相挑刺补充，上一轮看出 3 个问题，下一轮接着深挖，如同抽鞭子督促持续干活。

**效果**：多轮辩论纠偏后交付的审查深度和代码改进质量，远超任何单模型 one-shot——群体智能涌现，清华的研究也指出多 Agent 协同的群体智能远大于单个能力简单相加。

**代价**：Token 消耗指数级暴涨，通常是单次调用的 10 倍以上。黄东旭疯狂堆代码那阵子，**一天在 Slock 里烧掉 10 亿 Token，每天账单三四百美金**。这也是他后来必须把部分重复性大 Token 任务分流到本地开源模型、转向"Token Efficient"范式的最直接催化剂。

## 本地自研 Agent（本期最大亮点）

**做法**：本地开源模型 + 云端顶级闭源模型分层协作。

- **本地**：Mac Studio 跑 DeepSeek V4 Flash，速度 30 token/s（接近云端 API），满载一天电费约 $1
- 成本几乎归零 → 放开跑以前"舍不得用付费 API 做"的重活：批量总结 CVPR/NeurIPS 每年几百篇论文、整理个人数字足迹
- **云端**：本地多 Agent 团队卡在专家级 bug 上解不开时，让它们先写一份"为什么解不了"的报告，甩给云端最顶级模型（如 Fable 5）单点突破
- 云端 API 账单因此从爆表回落到正常每月两三百美金

## 观念转变的三个转折点

**转折点① OpenClaw 的出现**（标志"模型科研时代"转向"Agent 工程应用时代"）
2026 年 1 月左右，Peter 花一星期 vibe coding 做出 OpenClaw，宣告大模型推理与编程能力已经足够强，让有经验的工程师（而非科学家）能在极短时间内手搓出实用系统。

**转折点② 超级智力模型（Fable 5）发布，颠覆"三个臭皮匠"式开会观念**
以前需要 10 个 Agent 在 Slock 里反复讨论才能定位的地狱级 bug，甚至写报告承认"解不出"，在 Fable 5 面前 **one-shot 直接精准解决**。这让黄东旭反思：高成本的多 Agent 辩论策略未必还是最优解。

**转折点③ 实用级开源模型（DeepSeek V4 Flash、GLM-5.2）爆发**
过去开源模型太弱做不了复杂软件开发，现在能力已逼近第一梯队且实用。本地跑起来后，彻底改变心态，解锁了一堆以前"因为 API 太贵不敢做"的事。

**转变前后对比：**

| | 之前 | 现在 |
|---|---|---|
| 模型选择 | 无脑用最强最贵闭源模型（Token Maxing）| 讲究 ROI，性价比优先 |
| 消耗心态 | 疯狂烧钱刷榜（Uber/Meta 案例）| 追问"Token 花在哪、有没有浪费" |
| 对单点模型的信任 | 不信任，靠 10 个 Agent 开会兜底质量 | 顶级模型可以 one-shot，未必需要开会 |
| 关注重心 | 模型底层能力/科研 | Agent 软件工程（Harness Engineering）、可观测性、记忆/搜索/沙箱中间件 |
| 团队组织 | 单一昂贵 API 打天下 | 本地便宜员工干日常 + 云端顶级专家攻坚 |

## 投资看点

- **Agent Native 项目**：拿掉 Agent 元素后成本暴涨千倍或完全无法成立的那类项目，被认为最有价值
- **基础设施中间层**：记忆/数据平台、上下文管理、可观测性系统（帮 CIO 追踪 Token 到底花在哪）
- **Agent Cloud**（如 InsForge）：面向 Agent 而非人类开发者的新型云计算基础设施，融合沙箱环境+Serverless

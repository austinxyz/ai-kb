## 定义

Harness Engineering 研究的不是"怎样让 AI 写更多代码"，而是**怎样让不稳定的 AI Agent 在真实工程系统里稳定地产生价值**。Harness 可理解为"安全带""约束装置""测试线束"或"工程护栏"——不是限制 AI 能力，而是让能力可控地释放。

核心前提：**AI 是强大的工具，但不是可靠的组件。**

## 核心要点

**五条 Harness Engineering 原则：**

**原则 1：模型是不稳定组件，关键输出必须被验证**
- 不要因为回答流畅就认为它正确
- 不要因为代码能跑就认为它可靠
- 不要因为 Agent 说"完成了"就认为任务真的完成了

**原则 2：Query Loop 是 Agent 的心跳，必须有明确退出条件**
- 没有退出条件的 Agent 看似勤奋实则危险
- 它会不断尝试、修补、制造新的上下文，直到人类失去判断力
- YOLO mode 反模式：一步错，后续每步都建立在错误基础上

**原则 3：工具是执行接口，必须遵循最小权限原则**
- Agent 能做什么，比它知道什么更危险
- 每个能力（读/写文件、运行命令、访问网络、提交代码）都应审慎授予
- 权限边界是爆炸半径的硬约束

**原则 4：验证必须独立，不能让生成者成为唯一验收者**
- 写代码的 Agent 可以自查，但不能只靠它自查
- 独立验证机制：测试、静态检查、规则引擎、独立 Agent、人类 review

**原则 5：团队约束比个人手感重要，多 Agent 协作需要明确规则**
- 个人可以凭经验驾驭单个 Agent，团队不能只靠个人手感
- 团队需要：任务如何拆分、状态如何同步、冲突如何解决、产出如何验收

**把判断工程化（核心思想）：**
- 把判断变成可执行的规范
- 把风险变成可检查的条件
- 把权限变成明确的边界
- 把循环变成有退出条件的流程
- 把个人经验变成团队可共享的制度

**稀缺性重新分配：**
- 代码生成变便宜 → 真正昂贵的是判断
- AI 做快思考（执行、探索、生成）；人做慢思考（判断、审美、约束）
- Token 经济学：该省的不是 token，而是人的混乱、返工和误判

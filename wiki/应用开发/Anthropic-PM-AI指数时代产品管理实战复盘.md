## 摘要

16 个月内 Claude Code 完成软件任务的速度提升了 **41 倍**（METR 数据：Sonnet 3.5 需 21 分钟，Opus 4.6 近乎一遍过）。这打破了传统 PM 方法论的核心假设——"项目启动时的技术边界在项目结束时依然成立"。Anthropic 内部由此演化出一套 AI 原生产品方法论。

---

## 背景：地板不断抬升的隐喻

Cat Wu 养成了一个习惯：每次新模型发布，都让 Claude Code 尝试为 Excalidraw 添加表格工具。
- **2024.10 Sonnet 3.5**：每次失败
- **2025.6 Opus 4**：偶尔成功
- **今天 Opus 4.6**：稳定一遍过，可以在数千专业开发者面前现场直播

> 当"脚下的土地正在不断抬升"，PM 的节奏必须转变为：快速实验、持续交付、对有效的方法加倍投入。

## 三工具工作流矩阵

| 工具 | 定位 | 使用场景 |
|------|------|---------|
| **Claude.ai** | 战略思考伙伴 | 碰撞策略灵感、处理人际/项目情况，不需要它采取实际行动 |
| **Claude Code** | 智能工程机 | 构建原型、评估指标（Evals）、脚本。最终输出是代码就交给它 |
| **Cowork** | 知识大管家 | 清空收件箱、做幻灯片、搜索 Slack 历史还原决策上下文、预订差旅 |

> Decagon 产品总监：以前把想法变成可演示原型需要几周，现在几个小时就能搞定。

## 四大范式转变

### 转变 1：撕掉长期路线图 → 鼓励"支线任务"

- 传统：探索只能发生在锁定路线图**之前**
- 现在：鼓励所有人（工程师/PM/设计师）开启短期自驱的支线任务——花一个下午做原型，或测试"模型还做不到"的能力边界

**成果**：Claude Code 的桌面版、AskUserQuestion 工具、待办事项列表，都来自计划外的支线任务。

---

### 转变 2：原型 + 评估 暴打需求文档

- 取消传统站会，改为 **Demo 分享会**
- 神级技巧：写完功能文档后，直接扔给 Claude Code，它会立刻生成接近生产环境的原型，极大加速 UX 验证
- 用 **Evals（评估指标）** 量化功能何时有效/失效，改进不再是盲人摸象

---

### 转变 3：新模型发布 = 重新审视已有功能的隐式提示

- 每次模型发布，都是重新设计老功能的机会（可能原本能做得好 10 倍）
- **捕捉用户黑客行为**：用户手动把 Claude Code 代码复制到 Chrome 的 Claude 测试 → 直接启发了内置 Chrome 环境功能

> 核心警告：原型设计时，**永远优先为"模型能力"优化**。不要因为心疼 Token 成本而阉割功能——先验证算力拉满时是否可行，降本可以等模型变便宜后再做。

---

### 转变 4：大道至简，拒绝"技术补丁"

- 原则：做有效且**最简单**的事
- 为绕过当前模型缺陷设计的精妙补丁 → 新模型发布后变成纯粹的复杂债务
- **案例**：早期 Claude Code 待办事项需系统定期提醒模型更新。Opus 4.6 发布后这成了免费能力，立刻删除了所有提醒补丁，系统提示词缩减了 **20%**

---

## 冲浪隐喻：从微观控制到保持在浪头上

PM 的核心任务转变：
- ~~控制产品每个细节~~
- **圈定少数绝对不可妥协的底线，把剩下细节全部交给模型，让团队快速迭代**

终极效应：从"要不我们试试…"到"给，你试用一下这个"之间的开发时间差，几乎被完全抹平。
